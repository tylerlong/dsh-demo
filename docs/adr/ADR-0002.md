# ADR-0002: workspace as the orchestrator's session cwd

## Status

Accepted

## Context

A run needs a working folder: instead of every piece of context being spelled out in the task text, the user points a run at a workspace folder the run's agents can read for context. Every agent in the run (orchestrator and both workers) must share that workspace, and two lanes must be able to run against different folders in separate tabs. The harness gives each agent session a working directory (cwd); spawned child sessions inherit the parent's session cwd.

## Decision

The workspace becomes the orchestrator's session cwd: the orchestrator is created with `meta: { cwd: <workspace> }` instead of `process.cwd()`. Spawned workers inherit the parent's session cwd automatically (harness child-session cwd inheritance; there is no per-start cwd override), so both workers get the same workspace. The LLM sees the path through the harness `{{cwd}}` system-prompt variable, and read/glob/grep/bash resolve relative paths against the session cwd. `@deepseek-ai/dsh-agent-instructions` discovers AGENTS.md/CLAUDE.md by walking up from the cwd, so the agents pick up the repo's own instructions when present. No prompt change is needed.

The workspace is resolved and validated at submit time: relative paths resolve against the server cwd, canonicalized via realpath, and the folder must exist. An invalid workspace makes both lanes error before any worker spawns. Agents keep the workspace read-only; workers are already restricted to read-only tools so concurrent lanes never conflict over edits.

## Considered Options

- A per-start cwd override for each spawned worker. Rejected because the harness has no such override; the documented pattern is child sessions inheriting the parent's session cwd, which is exactly how workers get the workspace for free.
- Integrating the DSH Workspace registry (\`ctx.workspaceRegistry\`). Rejected for this change: the session-cwd mechanism is what reaches the LLM and the tools, so it is used directly and is out of scope.

## Consequences

- The acts of pointing a run at a folder and of giving every agent the same context are one mechanism: there is no separate "workspace" plumbing beyond the session cwd.
- Per-tab isolation falls out of per-run `RunRequest.workspace`: two tabs can target different folders because each run carries its own workspace.
- Because workers inherit the orchestrator's cwd via the harness, a future per-start cwd override, if one ever appears, could replace the inheritance without changing this ADR's intent.
