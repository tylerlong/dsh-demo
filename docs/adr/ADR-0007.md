# ADR-0007: read the left panel and active-session transcript like DSH web

## Status

Proposed (spec #59)

## Context

harness-workflow's left panel lists sessions from the shared DSH store read-only, but two reads diverge from DSH web:

- **The panel is slow.** Enriching each session loads and folds its full persisted log (`persistence.inspect` + `sessionQuery.readTitleSnapshots`), taking ~1.6s for the left panel on a fast machine with local content. DSH web does not re-read logs for the panel: it reads each session's `title` and `sessionListMetadata` (`{blank, lastPromptAt}`) from an in-memory projection cache (`sessionProjectionCache.cachedSnapshot`) that the apiproxy host checkpoints from the event feed.
- **The currently-active session diverges.** The most recent session — the one DSH web is actively working on right now — rendered with the placeholder label "Untitled session" and its transcript read failed, while DSH web showed that same session's real title and full history. The data is fully persisted; the difference is structural. The active session is the only one that went through a subagent/team turn (`agent/inbox/spliced`), which legitimately restarts the physical seq space at the splice (measured: exactly one seq regression, at physical line 753 of ~15k, preceded by `session/end-seed`; older sessions have zero). Our strict contiguous-seq transcript reader rejects the gap as corruption, whereas DSH web reads the live session from its attached in-memory session and never hits the persisted splice.

harness-workflow must show the same sessions, titles, ordering, and transcripts DSH web shows — but as a separate read-only process over the shared store. Read-only over `~/.dsh` is non-negotiable: the app must never write to the store DSH web owns.

## Decisions

1. **Left panel via the projection cache.** `loadSessionsFromContext` reads each session's `title` and `sessionListMetadata` from `sessionProjectionCache.cachedSnapshot(meta)` — a synchronous, zero-I/O in-memory look-up over the shared cache file, exactly the store face DSH web uses. `updatedAt = max(createdAt, lastPromptAt)`. Cache-missing sessions fall back to the existing log-fold + title read. This removes the ~1.6s per-session log reads and yields the active session's real cached title, killing the "Untitled session" divergence.
2. **The `sessionListMetadata` projection unit is registered by us.** Boot registers the unit exactly as DSH web does (api-proxy.ts): `{blank: boolean, lastPromptAt: number|null}`, init `{blank:true, lastPromptAt:null}`, `applySessionListMetadata`, `stateVersion:1`. The apiproxy host itself is not mounted (it drags in agents/llm/subagents).
3. **Labeling, ordering, visibility identical to DSH web.** Non-blank, non-archived sessions label `title ?? cwd-basename ?? id` (DSH `displayTitleOf`); there is no "Untitled session". Archived sessions are dropped via `workspaceRegistry.archivedSessionIds`. Per-workspace `updatedAt` desc, ties by id, top 5 ordering is preserved. Blank sessions remain filtered out (no provisional "New Session" row — deliberately simpler than DSH).
4. **Transcript tolerant of spliced child streams.** When `store.inspect` throws the seq-gap-at-splice error, `loadTranscriptFromContext` falls back to a tolerant decode of the raw JSONL (`persistence.readRaw`, verbatim decompressed text): keep the contiguous parent prefix, and resume after a seq restart that is licensed by an immediately-preceding `agent/inbox/spliced` / `session/end-seed` boundary (the spliced child stream resumes with its own lower seqs). Every line decodes with the same storage-record expansion the strict scan uses (`decodeStorageRecord`), so chunk rows expand to per-chunk events. A genuine missing range — a forward gap, or an unlicensed restart — is still rejected, never guessed. The `TranscriptStoreLike` seam and `convertSessionTranscript` stay unchanged; the pure fold is exported for reuse by the tolerant path.
5. **Strictly read-only, deliberately simpler than DSH.** Never write to `~/.dsh` (verified by hash-snapshot of a temp DSH home copy before/after boot + reads). No create/reorder/collapse/Ungrouped/expand-past-5/selection-persistence. **The e2e suite runs fully isolated:** `playwright.config.ts` boots the server with `DSH_HOME` pointed at a throwaway `test/e2e/.home` (seeded by `global-setup.ts` → `seed-isolated-home.ts`, which copies `settings.yaml`/`.credentials.yaml` from the real home and creates one fixture workspace + session through DSH's own services). Every write a run causes — resuming the fixture session, appending turns, lane subagent sessions, projection-cache checkpoints — lands only in that isolated home, never in the store DSH web owns. A read-only e2e test additionally asserts GET `/api/sessions` + transcript reads never mutate the isolated home (store fingerprint before/after). The real `~/.dsh` is never read or written by the suite.
6. **No changes to DSH packages.** All work lives in harness-workflow; the tolerant decode is owned on our side because we read the shared store read-only and do not own/amend `dsh-session-persistence-jsonl`.

## Considered Options

- **Keep re-folding every session's log for the panel.** Rejected: ~1.6s per panel load, and it cannot read the live session's log mid-write — the exact divergence this ADR fixes. The projection cache is the same store face DSH web itself uses.
- **Loosen the transcript seq check globally (tolerate any gap).** Rejected: a genuine missing range is real corruption and must stay rejected; only a seq restart at a splice boundary is licensed, mirroring how the strict scanner already tolerates a torn tail.
- **Amend `dsh-session-persistence-jsonl` to tolerate splices.** Rejected: we read the store read-only and do not own DSH packages; the tolerant decode lives in harness-workflow where it is testable in isolation.

## Consequences

- The left panel loads from the projection cache (zero-I/O) and matches DSH web's titles, ordering, and visibility, including the live session's real title.
- The active session's transcript renders its fully-persisted committed history; older clean sessions render identically via the strict path.
- The seam shapes stay narrow and read-only; the read-only guarantee is covered by tests (only `list()`/`inspect()`/`readRaw()`/`cachedSnapshot` are ever called, never a mutation).
- The e2e suite runs against an isolated `DSH_HOME`, so no test run ever resumes or writes the live session, and the read-only guarantee is asserted at the store level (fingerprint before/after reads).
